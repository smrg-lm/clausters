A panel that keeps its own undo: what the hand did to a synth's controls. A panel of a synth's controls has no document behind it, and a control bound to the synth sends its value straight to the server with this script out of the loop (bind.html), so the script cannot keep what the hand did. The window can: view({ history: true }, ...) gives it an undo order of its own, kept by the GUI host, and Ctrl+Z / Ctrl+Shift+Z walk it there. Two windows, one synth each, show what the order holds and what it does not:
  • A gesture is one entry. Drag the freq knob around and let go: one Ctrl+Z takes the whole drag back. A run of wheel notches or arrow keys on one control is one entry too, and so is what was typed in a field while it held the keys.
  • The target is the parameter. The freq field is bound to the same synth control as the knob, so the two are one target: undo a drag of the knob and the field shows it too.
  • Undo writes the value it had. Click nudge from the script: the script sets the synth's freq itself, the controls follow it on their read-back, and nothing is recorded. Ctrl+Z then writes the value the last entry stored, whatever the synth holds now.
  • The clipboard is the host's one. Click the knob in one window, Ctrl+C, click the knob in the other, Ctrl+V: the value travels as text (paste it in a text editor too), and the paste is one entry of the window it landed in. Anything else on the clipboard (a range of samples an editor copied) is refused, and the status line says what it holds.
  • Two windows are two orders, and Ctrl+Z in one never reaches the other.
  • A target that is gone leaves the order. Click free the synth in the second window: its node ends, and Ctrl+Z there says there is nothing left to undo. The status line says each step.
