The standard elements at their defaults, in every layout. One view holds the same set of standard controls -- a label, a button, a toggle, a choice, a number, a knob, a slider, a text field, a progress bar and a separator -- five times over, each time in a different container, and with nothing asked of any of them: no w, no h, no weight, no pack. So what is drawn is what the layout does with an element's defaults:
  • a row as wide as the view: how the width is shared along it;
  • a tall row (h: 140): what each element does across a cell taller than it is;
  • a short row (h: 28): what each one gives up in a cell shorter than it is;
  • a grid of four columns: an element in a cell it did not choose;
  • a column, on the right: how the height is shared down it.
No element is drawn under its floor, the smallest size it still reads at: the short row grows to its tallest control's floor rather than spilling into the grid under it, a knob gives up its caption before its disc, and the view is never made smaller than all of it. Filling a cell is the default -- a grid of buttons is a step sequencer -- so the buttons are as big as their cells. A sixth container is the other half: design. The same buttons in a grid, each told the most it takes (max_w, max_h) and where it stands in a cell larger than that (anchor).
