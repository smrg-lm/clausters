The web port of the Python client's osc_responder.py: the client as a hub — what arrives drives what is sent. An OscFunc registers a callback that fires when a matching message arrives, and that callback may send onward. Here a def reports its own onsets with SendReply; a responder hears them and answers each one with a synth, so the piece is played by the messages coming back rather than by a loop in the script. Two more watch the server's own notifications (/node_start, /node_end) and keep the count of what is alive, and a fourth follows the shared transport grid the way the Python example's second half does. Where the reference client binds a UDP port any application can target, a page has no socket to bind: its receiver is the carrier it already has — this engine's connection — so src reads page rather than a host and a port. Over Session.live(url) the same code listens to a native server and src is that socket's URL. Everything below runs on the in-page engine: no server process.
