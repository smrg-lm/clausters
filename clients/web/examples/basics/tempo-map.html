The web port of the Python client's tempo_map.py: a piece's whole tempo history, as a function you can ask — the same piece, question for question. A beat is not a unit of time. It is a logical coordinate, and what turns one into a second is the tempo — which changes along the piece. So "when does beat 8 happen?" has no answer from the tempo in force now: it depends on every tempo change before it. That function is the piece's TempoMap, and this page is about using it as a thing you interrogate rather than as a number a clock happens to hold. Its sibling tempo-canon.html is about one gesture — ten ramps in wall clock, landing together. This one is about the map underneath that gesture. Three things it shows, and the third is the one that catches people. A tempo change is recorded, never a replacement, so the beats before one still convert correctly afterwards. A length in beats is not a duration: the same eight beats last eight seconds early in this piece and rather less once the tempo has doubled, so seconds always come from two positions. And an accelerando is a logarithm — averaging the two tempos is out by a tenth of a second over four bars. Then the map is handed to a clock and the piece is played, so the acceleration is something you hear. The same map that answered the questions is the one the clock runs on: there is one function, not a description and a performance. What is different from the script, and it is only the platform: the numeric core is wasm and has to be fetched before anything calls into it (await loadCore(), which a script does not need because the same code is already in the process), the engine is the tab's own (Session.embed is this client's live), reading the map's rows is tempoSegments(map) rather than map.segments() because the map is a generated wasm class that cannot grow a method, and the watching loop is a timer rather than a sleeping main thread — a page has no thread to block. Every other line is the call the script makes, in the order it makes it. Build first (./build.sh from clients/web), then serve this directory and open the page.
