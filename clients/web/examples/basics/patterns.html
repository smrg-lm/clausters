The web port of the Python client's patterns.py: patterns are descriptions you walk, compose with operators, and play together -- and a voice whose notes go on into one another. A pattern is a description, walked by a loop. pseq(steps).add(67) is a pattern of MIDI notes made from a pattern of steps and an operator, and a plain for loop over it prints its values -- no clock, no server. The steps come from pyramid, a list function: it reshapes the whole list before it becomes a pattern (a list function reads a whole list, an operator one value at a time). A voice is articulated by its legato. The melody is a pvoice: each note's legato says how it goes on to the next. Where it is 1 the note is joined to the next -- the server keeps one synth and sets its freq, which has a lag, so the line glides -- and where it is less the next note re-attacks. Rendered into an event sequence, the same joins are a page's ties and slurs, printed below. Patterns play together. A counter-line from a pbind -- pxrand never repeating a note, pstutter doubling its durations, pmeanrand keeping its level near the middle -- runs beside the voice under ppar, merged in time. The session is seeded, so the draws are the same on every run and in both clients. The take is the render verb's, which goes on for a tail after the last event so the last note's release is not cut.
