The web port of the Python client's panic.py: stopping everything at once, and what it leaves standing. Three things sound here, each kept going by something different: a drone, a node that plays until it is freed; an arpeggio, a routine on the session's clock that makes a new note every quarter beat; and a responder, an OscFunc that would answer a message. Freeing the nodes alone does not stop that: the routine makes the next note a moment later, and a bundle already queued on the server makes one too. panic is the one verb for all of it -- sclang's CmdPeriod. It empties the session's clocks, halts its timelines, silences its server (every transport stopped, every queued bundle dropped, every node freed) and frees every responder not marked permanent. It closes nothing: the clock keeps its beat and goes on running, and the note played after it sounds. The free-standing panic() stops the session in force, the one an ambient play reaches; session.panic() names one. What is different from the script, and it is only the platform: the engine is the tab's own (Session.embed is this client's live), a page starts sound only from a gesture, so the three steps the script takes on a timer are three buttons here, and the calls that reach the engine are awaited. Every other line is the call the script makes, in the order it makes it. Build first (./build.sh from clients/web), then serve this directory and open the page.
