The web port of the Python client's composer.py: compose the arrangement, edit it on screen, hear it, undo it — the same composition, lane for lane. gui.FormEditor is the bridge between the arrangement (form — elements placed recursively by offset) and the multitrack view (tracks of clips on one shared time axis). It draws the arrangement tree as a GuiDef, applies the clip edit-backs the host sends onto the arrangement, and re-renders it. So the thing you drag is not a picture of the music: it is the music. Four lanes, and each is a different primitive. drums holds two Vectors over two different takes, each bounced offline in this tab and installed as a server buffer — the host fetches and decimates them, so a real take never rides the wire as JSON. bass is a Sequence over a pattern: a generator, bounced in the same pass that draws it, so the lane shows the notes it is about to play and the roll is read-only (a rendering of an algorithm is not a thing to drag). lead is a Track of clangs — those notes are editable. And sweep is an aggregate whose members start and end together, so it draws as one clip with layered bodies: the curve over the note it shapes. Press the curve and you edit the curve; press the clip's background and the clip is back in hand. Drag a clip to move it, its edge to trim it. The gesture leaves the host as an intent — where the hand put it, absolute — and the shared crate decides what it becomes: the musical quant grid snaps it there, not here. With follow on, the composition is re-scheduled from the playhead on every edit, so you hear the clip where you dropped it. With the pointer over a clip, e cuts it in two and j joins it back with what touches it — the two halves are two windows onto one buffer. The same two letters do the same thing on the melody clip, in beats instead of seconds: the halves are two windows onto one timeline, and the notes the cut hid are still on it, so dragging the second half's head back to the left brings them out again. The view never re-frames itself. The editor is built with autofit: false, which says the picture is yours. One switch with three faces, because a view fits itself to what is in it in three places: the time axis stays where you left it when the composition's length changes, a roll's pitch range stops re-centring when you drag a note, and a clip whose length nobody stated stops resizing itself when you move the last note of the phrase inside it. It is off here and on by default in the host: in an editor the content change is nearly always your own edit, and an edit that re-frames the view is the window starting over under the hand that made it. Drag a clip onto another lane and it follows your hand down the stack; the drop is one edit, so Ctrl+Z puts it back where it came from in one step. It is the same call that moves a note between rows in a roll — a lane and a semitone are one structure — and an edge drag never does it, since a trim is a length. Drag over a lane's empty space and you sweep a marquee: the clips the rectangle covered go into your hand and are drawn in the selection's colours — of every lane it crossed, since the stack is the sweep's second axis. A multitrack selects boxes, exactly as a patcher's canvas does, and it is the same gesture: the machine sweeps, and each view answers what fell inside. The rectangle is the gesture's own picture and goes with your hand; a time range over the same lanes is a different selection (the span a transport loops inside), asked for by name with gestures: {drag: "select"}. A click is a rectangle of no size, so it catches nothing and lets go of everything — and it puts the transport's cursor where you pointed. Alt+click adds or removes one clip (the same key that adds a note to a roll's selection, which is why it is this one and not Ctrl: over a roll, Ctrl removes a note). Grab any held clip by its body and the whole block moves rigidly — every held clip, on whatever lane — and Ctrl+Z puts all of them back in one step: one gesture is one edit, which is why the host reports a block as a single message ("clips") the owner applies as one transaction. Press q over the lane and the clips in hand quantize onto its own grid, the same grid a drag already lands on. An edge is always one clip's. Undo and redo are the buttons, or Ctrl+Z / Ctrl+Shift+Z over the window. The history is not this editor's: it lives with the document, in the same Rust crate both clients bind. Save writes the composition and where its samples are, and open reads it back — the same document the Python example keeps beside its takes, kept in the browser's own store instead, because a page has no folder to write a WAV into. What the document names, this side supplies: the take comes back as a buffer, the curve is handed back by name, and the pattern lane comes back frozen, since a reference to code is not something a name can find. Everything runs on the in-page engine: no server process, no socket.
