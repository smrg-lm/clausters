Reopening a multitrack: a saved session opened and edited. edit-multitrack.html builds its multitrack in memory and saves it as a session -- its takes as files, the join as the parts it is made of, the notes in the file itself, and the multitrack that names them -- into the page's own filesystem (the origin private file system, opfs). This opens that file the way any program would. Opening (Session.open) gives the multitrack and its source table back, and nothing more: every box names a source id, and a source says where it is. Editing is edit over the session: the multitrack, the GUI host's application, reads each take from the file beside the session, the join from the takes it is made of, and the notes from the file -- the same opening the standalone editor does. The join plays the glide's first half and then the saw's second, the parts the file states; the box on the keys track plays the notes the file holds, as the roll left them if a save came after an edit -- double click it to open the roll again. Save writes the session back. What it needs: open edit-multitrack.html once first, on the same origin, which saves out/edit_multitrack.json and its takes.
