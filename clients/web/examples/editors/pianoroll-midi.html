Paint a MIDI keyboard into the pianoroll, from the client. The web port of the Python client's examples/editors/pianoroll_midi.py, and the recording leg of pianoroll.html (that one draws and plays a scale; this one writes the roll from what you play). A MidiFunc pair listens on a MIDI input port and paints each key into a named roll with /gui_set: a note-on appends a note at the beat the session clock is on (counted from the first key down), and the matching note-off writes its real duration. The host has the same feature natively — open the roll with midiIn and route a device into the host's own port — and both legs exist on purpose: the native one records with no client in the loop, this one puts the notes under the script's control (they are a plain array here, so the take can be quantized, transposed or played before it goes back to the roll). To sound a keyboard instead of drawing it, see ../io/midi-responder.html. The one difference from the script, and it is the platform's: the Python client opens a virtual input port named clausters-in that you wire a keyboard into. Web MIDI creates no ports — it hands a page the ones that already exist, after asking your permission — so this picks one from that list. Plug the keyboard in, press open, allow MIDI, and play.
