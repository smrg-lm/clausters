The web port of the Python client's score.py: engraved music notation, clickable and editable. This page engraves a melody with verovio compiled to wasm — the same pinned sources, the same build options and the same version the native client links — and walks the SVG into the host's score display list with the same shared core. The host tessellates that into its ordinary mesh: it never reads a note, and it has no engraver in it. Every primitive carries the MEI xml:id it was engraved from, so a click reports the element under the cursor and this script sounds that note, and a vertical drag reports the diatonic staff position the note reaches — absolute, so a resend cannot move it twice. This side applies it (transposeTo), re-engraves and sends the page back; the ids survive the edit, so the note stays selected. Undo and redo are the client's too: the score owns a stack of MEI snapshots, because the host holds no score. The engraver is loaded on demand — it is not part of the runtime, and a page that draws no notation never downloads it. The page also plays, and the cursor follows the sound: the transport is the shared one — the same object the multitrack editor drives its lanes with — and all a score adds is its unit, since a page places its cursor in score milliseconds and a lane in samples. The line itself is the host's: one anchor message per pass, swept from the engine's own clock, and a static cursor where a pause left it. Everything runs on the in-page engine: no server process, no socket.
