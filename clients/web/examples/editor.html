The web port of the Python client's gui_editor.py: the editor-grade views, and a transport over them. A sound file goes into a server buffer — decoded by the browser and installed into the engine in this page — and the GUI host draws it as a waveform and a spectrogram, pulling the samples over its own client leg. Both views are linked, so the wheel zooms and Shift+drag pans them together; a plain drag selects, and the selection comes back to this script as a /gui_event. The transport is part of the same window: play starts a PlayBuf and anchors the host's playhead to the engine's sample clock — the line is then drawn from Rust every frame, at the display's rate and with no message per frame; pause is /n_run 0, which freezes the node with its buffer position intact, and parks the line where it stopped; stop frees it. play selection reads the selected region instead, with a Phasor looping between its bounds, and the line follows it: playhead_loop_start/playhead_loop_len make the host's own sweep wrap inside the region, so a repeating pass still costs one message and not one per frame. Nothing is drawn by this page: the canvas below belongs to the host. (For the other direction — the same data read by the script and drawn by hand — see scope.html.) Everything runs on the in-page engine: no server process, no socket.
