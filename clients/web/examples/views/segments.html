A take that is a list of segments over a file, drawn by the host. An application's takes live on disk: a take is a list of segments, each a span of a file with its own fades and channel map, and an edit is a new list over files that never change. This page renders one file and draws two lists over it, one above the other, both with waveform({ segments }):
  • the take as it is: one part, the whole file -- a four-second tone that swells from quiet to loud;
  • the take edited: the same file with its halves swapped, the loud half first, with a 10 ms fade either side of the seam. Nothing was rendered for it. It is two parts over the one file, and its picture is composed by the host from the file's peaks.
The file is rendered offline with its peaks beside it: the render writes the samples to take.w64, and a peaksOut on the same signal writes take.peaks, the summary a waveform is drawn from. The host reads both itself, with no server involved in the drawing: it reads the levels of the peaks its window resolves, and samples only under a zoom. So zoom in with the wheel until single samples show, and what you see is read from the file then, a span at a time. Check by eye that the edited take falls from loud to quiet at its seam and then swells again, and that zooming into the seam shows the 10 ms fades meeting.

The files land in out/segments/ of the page's own storage (the origin private file system), where the script writes them under clients/python/examples/out/segments/; a part names its file by that path in each. Needs ./build.sh in clients/web first (dist/ is git-ignored); serve it over HTTP and open /examples/views/segments.html.
