The web port of the Python client's scoping.py: watching live buses with the free-standing scope, and its three views. scope is the real-time sibling of plot: where plot draws a finished render, scope opens a window that follows live audio buses, frame by frame. One rule covers every view — the verb monitors channels consecutive buses from bus, and each view presents them its way: oscilloscope lanes, the stereo phase field, one spectrum curve per channel. Naming the bus is all this page does; the host asks the server to record it and stops when nothing draws it any more. Watch the oscilloscope's corner read-out: lock means the trigger found a rising crossing and the trace stands still (the faint line marks the level); free means it is free-running — silence or DC. Where the Python example is a timed tour that opens each window alone, this one puts the three side by side and leaves the knobs under your hand: spread crossfades the right channel from a copy of the left (mono — the goniometer draws a vertical line) to a detuned sine (decorrelated — the trace opens into the lozenge), and the view controls go through win.set(...) live. The control is lagged, because a /node_set lands as a step and stepping a crossfade clicks; the scopes themselves are passive — a tap only copies a bus and can never alter the sound. One difference from the desktop, and it is the browser's: the native host reads the taps out of the server's shared-memory segment, and a tab has no segment to map, so the host streams them over its own server leg instead. The verb is the same either way — that is the point of it. Everything sounds through the in-page engine: no server process, no socket.
