The three data paths of a running server, each with the view that reads it: a control bus (an LFO) under a meter, an audio bus (a tone) under a scope and a spectrum, and a buffer under a waveform. This script names what to look at and draws none of it. A GuiDef says gui.scope(bus), gui.spectrum(bus), gui.meter(bus), gui.waveform({ buffer }) — a bus number and a buffer number — and the GUI host subscribes, measures and paints: the trigger that makes the trace stand still, the decibel curve, the peak columns and the join that inks an edge are all its, out of the same clausters-core the server computes with. There is no canvas in this page and no arithmetic over samples; the whole of the client's part is the tree below. The tone's freq knob is bound: its value goes from the host straight to the engine as a /node_set, never passing through this script. freeze is the other path — it comes back as a /gui_event and this code sets the scope's hold, so both directions are visible at once. One reader per page. Over the in-page carrier the script and the host reach the engine through one shared-memory ring, which the server sees as a single client — so a subscription the script opens and one the host opens displace each other. Here the host is the reader, which is the ordinary case: what a page wants of a live bus is almost always to see it. Everything runs on the in-page engine: no server process, no socket. Swapping to a --ws server (or to a native clausters-gui --ws host) is one line each, marked below.
