The web port of the Python client's views/layers.py: the layer stack — a spectrogram, the wave over it, and the level inside that. A view of a signal draws several things on one body, and layers is the list of them, back to front. It is one element and not three stacked widgets, because every view of a signal paints its own field before it draws: a second one on the same rectangle would be a lid over the first, not a layer over it. One element is also one time axis, one selection, one playhead and one upload. The order is yours — the texture, then the wave, then the level. The vertical belongs to one layer: a spectrogram measures hertz and a wave measures amplitude, so the texture keeps the axis (the Hz ruler is its) and the curves say y: "box", which normalizes each into the body it is drawn on; two layers claiming the axis is refused, and the last button asks for it so you can read what comes back. Alpha is per layer: the two sliders re-state the stack live, so the curves fade over the texture while the picture under them stays where it is — not the widget's opacity, which would fade the rulers with it. Solo and hide read a stack while you build it: a hidden layer keeps its place in the order. The take is four seconds of a sweep from 300 Hz to 3 kHz whose level steps down halfway, built at 16 kHz: the sweep is a diagonal in the texture and the step is a cliff in the wave, so the two layers say visibly different things about the same samples. It makes no sound. Needs ./build.sh in clients/web first (dist/ is git-ignored); serve it over HTTP (python3 -m http.server) and open /examples/views/layers.html.
