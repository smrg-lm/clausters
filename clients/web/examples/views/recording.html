Four takes drawn while they are recorded. The web twin of the Python client's recording_mapped.py.

Press start, then record 4 takes: four glissandi play and each is recorded into its own buffer. A native host reads those buffers from memory it shares with the server; a page cannot, so the server sends a summary of what was just recorded (/buffer_stream) and the page draws it. The audio itself is never sent.

Zoom with the wheel and pan by dragging. Zoomed in, the page asks for the samples of the span on screen.

The second button stands for another client editing a take: it silences the middle of the first one and says which span changed (/buffer_touch). The page reads back only that span.

Everything runs in the page: no server process.
