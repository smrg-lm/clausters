Bounce a phrase offline, then play it back from the file the render wrote. This is the change of state the render verb is named for: a generator thing (a pattern -- an algorithm that describes sound) becomes a generated one (a file -- random-access audio you can slice, loop and read backwards). The file needs no conversion in between, because the same server code wrote it and reads it:
  1. An offline session plays the phrase and renders it with a path: the take is written to out/phrase.wav in the page's own filesystem (the origin private file system). What comes back is the stats -- frames, events, per-channel peak and RMS -- and no samples.
  2. readSoundfile brings the samples into the page through the server's own decoder, and the numbers match the render's own stats.
  3. A live session starts and Buffer.read (/buffer_allocRead) loads that same file into a server buffer: float32 WAV, read by the decoder the server already ships.
  4. A playBuf synth plays the buffer -- the take, sounding as a sample.
Needs ./build.sh in clients/web first (dist/ is git-ignored); serve it over HTTP and open /examples/buffers/render-then-load.html.
