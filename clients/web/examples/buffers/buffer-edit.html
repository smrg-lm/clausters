Editing a buffer from the client: read the samples, change them, write them back. A buffer is the one thing a piece keeps with random access — so unlike a stream of events it can be read backwards, sliced and edited in place. The point of interest is that whole round trip, done three times on one buffer, each edit audible against the one before: Read a sine1 table the server generated. Edit, then write: the samples are reversed here and written back — a symmetric waveform survives that unchanged, so the second edit is the one that speaks, a fade carved into the table which turns a steady tone into one that swells and dies inside every period. A single sample by flat index is the touch-up form. A write past the end is refused instead of being clamped the way a read is: a short read hands back less and says so, a short write would drop samples you believe you stored. The edits the server does for you — gain, fade, silence, reverse — say what the edit is and no samples cross the wire at all, which is the difference between editing a table and editing a five-minute take.
