The web port of the Python client's gui_score.py: engraved music notation, clickable and editable. This page engraves a melody with verovio compiled to wasm — the same pinned sources, the same build options and the same version the native client links — and walks the SVG into the host's score display list with the same shared core. The host tessellates that into its ordinary mesh: it never reads a note, and it has no engraver in it. Every primitive carries the MEI xml:id it was engraved from, so a click reports the element under the cursor and this script sounds that note, and a vertical drag reports the diatonic staff position the note reaches — absolute, so a resend cannot move it twice. This side applies it (transposeTo), re-engraves and sends the page back; the ids survive the edit, so the note stays selected. Undo and redo are the client's too: the score owns a stack of MEI snapshots, because the host holds no score. The engraver is loaded on demand — it is not part of the runtime, and a page that draws no notation never downloads it. Not here yet, and not a defect of this page: the Python example also plays the score with a transport bar, the cursor following the sound. That transport is shared with the multitrack editor, which this client has not ported; the score half lands with it. Everything runs on the in-page engine: no server process, no socket.
