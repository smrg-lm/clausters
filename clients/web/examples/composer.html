The web port of the Python client's gui_composer.py: compose the arrangement, edit it on screen, hear it, undo it — the same composition, lane for lane. gui.Editor is the bridge between the arrangement (form — elements placed recursively by offset) and the multitrack view (tracks of clips on one shared time axis). It draws the arrangement tree as a GuiDef, applies the clip edit-backs the host sends onto the arrangement, and re-renders it. So the thing you drag is not a picture of the music: it is the music. Four lanes, and each is a different primitive. drums holds two Vectors over two different takes, each bounced offline in this tab and installed as a server buffer — the host fetches and decimates them, so a real take never rides the wire as JSON. bass is a Sequence over a pattern: a generator, bounced in the same pass that draws it, so the lane shows the notes it is about to play and the roll is read-only (a rendering of an algorithm is not a thing to drag). lead is a Track of clangs — those notes are editable. And sweep is an aggregate whose members start and end together, so it draws as one clip with layered bodies: the curve over the note it shapes. Press the curve and you edit the curve; press the clip's background and the clip is back in hand. Drag a clip to move it, its edge to trim it. The gesture leaves the host as an intent — where the hand put it, absolute — and the shared crate decides what it becomes: the musical quant grid snaps it there, not here. With follow on, the composition is re-scheduled from the playhead on every edit, so you hear the clip where you dropped it. With the pointer over a clip, e cuts it in two and j joins it back with what touches it — the two halves are two windows onto one buffer. Undo and redo are the buttons, or Ctrl+Z / Ctrl+Shift+Z over the window. The history is not this editor's: it lives with the document, in the same Rust crate both clients bind. The one thing the Python example does and this does not: save the session to a file and open it again. A page has no folder to write the takes' WAVs beside the document; the arrangement, the editing and the history are the same code either way. Everything runs on the in-page engine: no server process, no socket.
