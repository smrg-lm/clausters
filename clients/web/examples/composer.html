The multitrack lanes in the browser: four tracks of clips on one shared time axis, drawn by the GUI host. The three clip bodies are all here — a take (a server buffer, decimated by the host through its peak pyramid), two piano-roll clips of notes, and an automation curve edited in place. This is the host half of the Python client's gui_composer.py, and only that half: the lanes and clips are built here as widgets, so there is no arrangement model behind them (no clausters.form, no Editor) — an edit-back is logged, not applied to a tree and re-rendered. What it does carry faithfully is everything the host owns: the shared axis, the drag grid, the clip gestures and the navigation. The axis is navigable: wheel zooms, Shift+drag pans, and every lane moves as one because they share a link group. Drag a clip to move it, its edge to resize — both snap to the snap grid and come back as a "clip" event. Inside a clip, drag a note or a break-point. Everything runs on the in-page engine: no server process, no socket.
