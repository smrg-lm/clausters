The web port of the Python client's sync.py, call for call: two independent clients phase-aligned on one server's shared transport, and a playhead that obeys the conductor. What the page adds is the hand — the script runs the same sequence start to finish, and here each step is a button, so a late join can be pressed late. The server keeps one transport: a beat grid (originSample, tempo) a conductor writes with server.setTransport(...), plus a rolling state. Any client can join that grid with clock.joinTransport(server) (or session.joinTransport()), and from then on a quant-ed start snaps to the shared bar line rather than to "four beats after I happened to start". That is the whole trick: the two clients below are as independent as two browser tabs — their own Server handle, their own TempoClock, their own slice of the id space, started seconds apart — and they agree on nothing except three numbers each read once. The conductor boots the server they share; they only attach to it. The second half is the rolling state. server.transportPlay() / transportStop() / transportLocate(beat) are broadcast to every client registered for notifications, and playhead.followTransport(server) turns those broadcasts into this page's transport: the conductor rolls, halts and seeks every follower at once. The server broadcasts control, never audio. What to listen for: press "join late" while the first client is already waiting — the two notes still land as one attack on the next bar, and however late you press it the offset never accumulates. Needs ./build.sh in clients/web first (dist/ is git-ignored). Open it over HTTP: python3 -m http.server, then /examples/transport/sync.html.
