# The chapters both client books share

The Python client's book (`clients/python/docs/`) and the web client's
(`clients/web/docs/`) are two books of one client in two languages, so the
chapters they share are written once, here, in `src/`. Each book's chapter of
the same name is one line that includes it:

    {{#include ../../../docs/src/timing-models.md}}

and `shared_book.py`, which both books run as an mdBook preprocessor, turns
the shared text into the book's own. The same module makes the copies the
packages carry (`clients/python/build_docs.py`, `clients/web/tools/stage_books.py`).

## Writing a shared chapter

- **An example is written in both languages**, a `python` block and a `ts`
  (or `js`) block next to each other, with nothing but blank lines
  between them. Each book keeps its own. The two are the same calls to the
  same API in the same order; an example in one language alone stops the
  build. A block in another language (`sh`, `text`, `toml`, `html`) is the
  same in both books.
- **What only one platform has** goes between `<!-- python -->` and
  `<!-- /python -->`, or `<!-- web -->` and `<!-- /web -->`: a paragraph, a
  table, a few words inside a sentence. A code block inside one needs no
  pair. Markers do not nest.
- **A short alternative inline** is `{{alt A || B}}`: `A` in the Python book,
  `B` in the web one. It is for a call spelled with keyword arguments in one
  language and an options object in the other, or a page each book names
  differently.
- **An API name** is `{{api buffer_alloc}}`, in the Python client's spelling.
  The web book spells it in camelCase (`bufferAlloc`), or as `names.toml`
  says where that rule is wrong. Where the web reference is generated, a
  spelling it does not document stops the build, and so does a snake_case
  name in backticks that the Python reference documents: that is a Python
  spelling which reached the web book.
- **A property is a property in one client only, sometimes**: where Python
  assigns (`editor.entry = True`) the web client may have a setter
  (`setEntry(true)`), so the call goes in an `{{alt}}`. An assignment in the
  web book to a member its reference has only as a method stops the build.
- **A name that is the wire's in both clients** (a GuiDef axis key,
  `sample_rate`) is `{{wire sample_rate}}`: the same text in both books, and
  exempt from that check.

What only one client has stays in that client's book (`cli.md`,
`configuration.md`, `components.md`, `platform.md`), and each book's API
reference stays generated by its own tool.

`scripts/check-docs.sh python web` builds both books, and
`clients/python/tests/test_shared_book.py` checks the rules above.
