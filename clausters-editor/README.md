# clausters-editor

A lightweight Python editor with an interactive session: an editor, a *post*
window with the output and a Markdown documentation viewer. Tauri 2 + Svelte 5 +
CodeMirror 6. The interface uses [shadcn-svelte](https://shadcn-svelte.com)
(Neutral theme) and Tailwind; the editor uses VS Code's syntax colors.

It lives in the `clausters` repository but is independent of it: every command
and path below is relative to this folder (`clausters-editor/`), not to the repository
root.

## Requirements (Ubuntu/Debian)

```sh
sudo apt install libwebkit2gtk-4.1-dev build-essential curl wget file \
  libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev
npm install
```

## Usage

```sh
npm run tauri dev      # development, with hot reload
npm run tauri build    # binary and packages in src-tauri/target/release/bundle
```

## Installing for the user

```sh
./install.sh install            # builds and installs into ~/.local (binary, docs, menu entry)
./install.sh update             # rebuilds and replaces (works with the app open)
./install.sh uninstall          # removes the installation; keeps configuration and environments
./install.sh uninstall --purge  # also deletes configuration, virtual environments and cache
```

Options: `--prefix DIR` (another destination), `--no-build` (use the binary
already built), `-y` (no confirmation). See `./install.sh --help`.

### A test installation

To try a version without touching the real installation or its data: install it
into a temporary folder and redirect the XDG folders where the app keeps its
configuration, virtual environments and cache.

```sh
T=$(mktemp -d)
export XDG_CONFIG_HOME=$T/config XDG_DATA_HOME=$T/data XDG_CACHE_HOME=$T/cache

./install.sh install --prefix "$T/pfx"
"$T/pfx/bin/clausters-editor"             # the app starts with no previous configuration or environments

./install.sh uninstall --purge -y --prefix "$T/pfx"   # deletes only what is in $T
rm -rf "$T"
```

The XDG variables only affect the terminal they are exported in; closing it (or
`unset XDG_CONFIG_HOME XDG_DATA_HOME XDG_CACHE_HOME`) goes back to the usual
paths. The menu entry does not show up in the applications menu, because
`$T/pfx/share` is not among the folders the desktop looks in.

## Environments and configuration

- **Virtual environments** (Session → Python Environments): created in
  `~/.local/share/io.github.smrg-lm.clausters.editor/venvs/<name>` with `python3 -m venv`, and
  the *install source* (the arguments of `pip install`, e.g. `/path/to/package`
  or `-e /path/to/package`) is installed into them. The session uses the last
  environment chosen, also after reopening the app.
- **Documentation folder** (File → Preferences, or the folder button on the
  documentation panel): any folder with `.md` files; by default, the one bundled
  with the app.
- **Startup code** (File → Preferences): runs at the start of every session.
- Everything is kept in `~/.config/io.github.smrg-lm.clausters.editor/config.json`.
- `CLAUSTERS_EDITOR_PYTHON=/path/python` forces an interpreter (it takes precedence over
  the environment).

## Layout

```
src/
  app.css                  shadcn theme (light/dark) and global settings
  fonts.css                the two bundled typefaces, Inter and JetBrains Mono
  App.svelte               menu, toolbar, the panel grid and its dragging, global shortcuts
  lib/components/ui/       shadcn-svelte components (generated by its CLI, not edited by hand)
  lib/AppMenu.svelte       menu bar
  lib/Editor.svelte        an editor: tabs + CodeMirror, open/save (one or two of them)
  lib/Grip.svelte          the handle every panel is dragged by
  lib/editorTheme.ts       editor theme: shadcn variables + VS Code syntax colors
  lib/evaluation.ts        what each shortcut evaluates (line, selection, block)
  lib/hints.ts             documentation tooltips and parameter help (from the session)
  lib/ui/tooltip.ts        themed tooltips for every `title` attribute on the page
  lib/Post.svelte          output window
  lib/Docs.svelte          documentation viewer, history, help (Ctrl+D)
  lib/markdown.ts          markdown-it + DOMPurify + highlighting
  lib/settings.svelte.ts   theme, font, size, panel layout and grid sizes (remembered)
  lib/session.svelte.ts    communication with the Python session
  lib/EnvironmentsDialog.svelte, lib/PreferencesDialog.svelte   configuration dialogs
src-tauri/
  python/driver.py         driver: runs the code in a persistent namespace
  src/session.rs           the Python process: start, send, interrupt, restart
  src/files.rs             the user's files and the docs/ folder
  src/fonts.rs             installed monospaced fonts
  src/config.rs            persistent configuration
  about.toml, about.hbs    the licenses `cargo about` accepts, and how it writes the crates' notices
  src/envs.rs              virtual environments (create, install, choose, delete)
docs/                      Markdown documentation (bundled with the package)
licenses/                  THIRD-PARTY.txt: the license of every package the app ships, shipped
                           with it -- `npm run notices` writes it (needs `cargo about`)
scripts/notices.mjs        what writes it: the Vite bundle's packages + `cargo about`
```

To add components: `npx shadcn-svelte@latest add <name>`.

### Third-party licenses

The app ships the license of every package it is built with, in
`licenses/THIRD-PARTY.txt`, because most of those licenses ask for it. The file
is generated, never edited, and it has to follow the dependencies: **adding,
removing or updating a library -- npm or Rust -- ends with `npm run notices` and
the regenerated file in the same commit.** CI runs `npm run notices -- --check`
and fails when the file is not current.

- **Before adding a library, check its license against GPL-3.0-or-later.** A
  crate under a license `src-tauri/about.toml` does not accept stops `cargo
  about` with an error: add the license to `accepted` only after that check,
  never to get past the error.
- **An npm package that ships no license file** stops the script, unless its
  `package.json` names MIT and an author, which then get the MIT text, marked
  as such. Anything else is for a person to resolve.
- What counts as shipped is read from the build, not from `package.json`: the
  packages the Vite bundle reads in, the stylesheets `src/app.css` imports, and
  the crates `cargo about` resolves for every release platform.

It needs `cargo about` (`cargo install --locked cargo-about --features cli`;
CI pins 0.9.2).
