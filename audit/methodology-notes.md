# Methodology improvements from the first campaign

Campaign: 2026-10-15, application commit 04f4b742ce1c8b11569c9533030eeba4ff596095, initial audit resources 2e376873. These are audit-tool/procedure findings, distinct from application defects. Corrections made in disposable copies and exact scenario snapshots remain in the campaign evidence. No application source fix is included. Evidence paths below are inside the campaign's archived record (`2026-10-15_04f4b742_01-records.tar.gz`), not in the repository.

| ID | Observation and evidence | Method improvement | State |
| --- | --- | --- | --- |
| A01 | The preparer creates an editor target symlink, but its directory-only ignore pattern does not ignore the symlink; the runner refuses its own prepared clone. preflight/target-link-repair.json | Do not create a target link for a builder that respects CARGO_TARGET_DIR; verify cleanliness after preparation using the real ignore layouts, not only synthetic fixtures. | Campaign repaired; reusable preparer fix pending |
| A02 | Release tests cannot import assert_no_alloc::AllocDisabler with disable_release; the GUI release test expects a Note compiled out without diagnostics. Original workspace/gui run logs retained. | Run correctness under debug or explicit diagnostic features; reserve release for measured workloads. Treat unsupported test profiles separately from production behavior. | Corrected scenario snapshots executed |
| A03 | Workspace feature unification pulls wasm engine dependencies into a native no-default run. Existing CI and the feature-matrix skill exclude the two wasm engine crates. | Read the actual target/feature build contracts before choosing an audit matrix; cover excluded crates via wasm gates rather than silently omitting them. | Corrected native selection; target gates recorded |
| A04 | A successful web build emits warnings yet lacks ignored third-party wasm assets; packaging tests fail before browser acceptance. | Preflight all required runtime assets, exact pins/hashes and build provenance. Distinguish package-source defects from unprepared optional-looking inputs. | Cached assets staged and identified; source attestation limits explicit |
| A05 | Web build regenerates two tracked .d.ts files, so the next run fails the clean-checkout gate. preflight/generated-web-bindings.patch | Capture generated output diffs separately from intentional instrumentation; define repeat-run behavior for reproducible generators. | Diff retained; only known generated files restored in the disposable clone |
| A06 | pytest -q terminates at a native SIGXCPU and loses the last test identity and summary. Verbose retry and GDB identify the PipeWire callback where SIGXCPU is delivered, not its origin. The maintainer reports no reproduction under Claude. | Always retain signal names, last test and process limits; use process isolation by file for suites crossing native/RT boundaries. Debugger traces diagnose behavior and are not timing evidence. Compare an identical binary outside the agent execution environment before attributing a product defect. | Verbose, isolated-file and debugger evidence collected |
| A07 | Failed commands bypass metric parsing: the GUI log retains 1310 passed and 1 failed but the numeric summary is empty. | Separate collection of test counts from verdicts; preserve successful samples/counts within failed suites, without promoting them to a pass. | Reusable parser improvement pending; report reads retained raw log |
| A08 | The owner requested no more than half the logical CPUs. Topology shows 20 logical CPUs, performance siblings at 0-11; selected 0-9. | Bound affinity for the whole process/thread tree, not only Cargo jobs. Capture topology and policy transitions. Explicitly document full-CPU experiments if required. | Active descendants constrained; later runs inherit 0-9, jobs/test threads 10 |
| A09 | Four independent Rust targets accumulated roughly 39 GiB before cleanup; incremental caches alone occupied about 7 GiB. | Record disk before each phase, choose a free-space floor, disable incremental for one-shot audits, clean only inactive generated caches, and archive needed evidence/artifact identities first. | Campaign uses 150 GiB free floor and CARGO_INCREMENTAL=0; cleanup receipts retained |
| A10 | One aggregate workspace test count does not establish every feature/target or every crate. | Keep per-manifest source/feature/target evidence and state sampled review limits. Exercise optional FFI/notation/plugin paths as independent contracts. | Inventories and supplemental gates retained; unsupported scope remains explicit |
| A11 | Original run blocks may be prerequisite failures, application failures, incomplete collection or reviewed negative evidence. | Keep audit completion distinct from product acceptance. Preserve failed/partial records with review reason and immutable hashes; never overwrite retries. | Evidence-only sealing supported |
| A12 | Browser acceptance runs in headless Chrome with software rendering. | Record renderer/driver and do not report software acceptance or requestAnimationFrame pacing as native GPU execution time or physical presentation latency. | Acceptance evidence labeled; real GPU claims excluded |
| A13 | Dependencies/builds can be shared prerequisites of independent checks, while the runner skips all later commands after any failure. | Represent actual dependencies between steps; independent lint/review should remain executable after a failed correctness check. Keep auxiliary commands and their environment as first-class evidence. | Supplemental independent gates used; reusable DAG improvement pending |
| A14 | fuzz is an independent workspace with an intentionally ignored, initially absent Cargo.lock; --locked cannot create it. | Generate its lock offline in the disposable clone, retain exact bytes, then lint with --locked. Keep stable lint distinct from sanitizer execution. Nightly/cargo-fuzz were initially unavailable, then installed explicitly at the maintainer's request in isolated tool roots. | Corrected lint passed; generated lock retained; bounded sanitizer run added |
| A15 | The real bench --json emits a JSON array; the synthetic parser test expected line-delimited objects and rejected a successful warmup. | Test parsers against the exact producer contract, retain raw arrays, and collect three repetitions without overwriting the original parser error. Never infer a benchmark failure from a collection error. | Supplemental array collection used; reusable parser fix pending |
| A16 | Supplementary GUI integration builds in a shared target cannot resolve the MIDI live module even after selecting the feature explicitly, while earlier host/default gates built successfully. | Preserve the failed attempts; isolate generated targets between independent workspaces/build configurations before attributing a feature defect. Stop repeated collection when build prerequisites fail. | Fresh target probe retained; cause and final outcome described in GUI measurement evidence |
| A17 | Moving the fuzzer changes resource paths after the measured application commit. | Keep measured source identities immutable, compare target/seed bytes across relocation, update path consumers, and record optional tool provisioning separately from application dependencies. | Existing implementation retained; isolated cargo-fuzz/nightly install and ASan execution recorded |
| A18 | Tool logs contain trailing spaces/final blank lines; an unstaged-only diff check does not inspect new evidence files. | Preserve captured bytes and hashes. Scope whitespace attributes to raw log/stdout/stderr captures, and check the staged diff before committing. Do not reformat sealed evidence. | audit/records/.gitattributes added; staged and campaign diff checked |
| A19 | E01 called the SIGXCPU origin unresolved, yet the project's own record explains it: the binary arms a SIGXCPU guard against RTKit's RLIMIT_RTTIME watchdog (src/server/rt.rs, root PLAN.md M24), and the embedded engine the Python suite drives does not, by design. A debug build sharing ten CPUs with concurrent compilations is the load that trips the watchdog. | Before calling a cause unresolved, search the project's plans, decisions and module docs for the symptom (here the signal's name). A cause the repository already documents is a finding about its scope, not an open environment question. | Explanation filed in the application's root PLAN.md, Found by use |
| A20 | F06 reported an absent plugin fixture. The file exists under another path (crates/clausters-plugin-host/tests/fixtures/clap.c), already used by tests/plugin_family.rs; the library tests named a path that never existed, and no CI job ran them. | When a test names a missing input, search the tree for it by name and by its contents' identifiers before reporting it absent, and check whether any job runs the failing test at all. | Fixed in the application; the reading is recorded here |
| A21 | Severities were ranked by the class of risk rather than by evidence and cost: an unreproduced structural concern was High while reproduced release-gate failures were Medium or Low, and a hand-fed REPL queue was Medium. | Rank a finding by what was observed, how likely the path is in the project's real use and what a fix changes. A structural concern with no reproduction and a semantic cost to fixing it is a future direction, not a High defect. | Applied in the disposition below (audit/PLAN.md) |
